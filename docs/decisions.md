# Decisions on record

The one decision log. It answers "why is it like this", so a future session
does not spend an afternoon rediscovering an answer somebody already reached.
The rules themselves live where they are enforced; this file is the reasoning.

---

## Product

| Decision | Rationale | Don't |
|---|---|---|
| A session never expires; it lives until logout, a password change, or a reset | A habit tracker is opened daily on the user's own device, and being signed out between check-ins is friction with no matching threat | Add an idle timeout or token TTL without asking |
| Password reset is proven by an authenticator code, not an email link | The brief rules out email verification and the stack has no mail service; the authenticator is the only second channel. The cost: an account without MFA cannot recover a forgotten password | Add a reset path that needs only the email address; that is account takeover by anyone who knows it |
| Email-first sign-in (`/auth/identify`) | The form can send a new address straight to sign-up instead of failing a password | Merge identify into login; the second screen needs the answer before a password exists |
| English-only UI, no i18n layer | The brief asks for none, and a translation layer is weight a lightweight app does not need yet | Hard-code copy in a way that blocks adding one later: keep it in the components, not in the API |

## Architecture

| Decision | Rationale | Don't |
|---|---|---|
| Fastify, not Express or NestJS | Built-in async error handling and a request lifecycle with hooks, without NestJS's module and decorator weight for a dozen routes | Wrap it in a DI framework |
| Shared pieces are `fastify-plugin` plugins in `src/plugins/`, route modules are plain plugins; both autoloaded | The Fastify skill's layout (`plugins.md`): a shared plugin decorates the root, a route module stays encapsulated under its own prefix, and `dependencies` order the loading | Import one route module's plugin from another, or register a shared plugin without `fp()`: its decorators would stay inside it |
| `env-schema` validates the environment once, at start | A typo in `PORT` or `LOG_LEVEL` stops the server with the variable's name instead of running on a fallback (`configuration.md`) | Add a default for `APP_KEY`, or check `NODE_ENV` in code |
| Sessions are checked by `@fastify/bearer-auth` with our own lookup | The official plugin parses the header; `auth(key)` does the `<id>\|<secret>` read. `addHook: false` so each protected scope adds `app.authenticate` itself and a database error reaches the error handler | Let the plugin add its own hook: its 500 path answers without logging the error |
| One `@fastify/error` class per refusal code (`lib/errors.ts`) | Typed errors the handler recognises by code, each with the field it belongs to (`error-handling.md`) | Refuse with `reply.status(…).send(…)` in a handler: it skips the envelope |
| Secrets come from `.env` or are generated on first boot; never a literal or default in code, tests or `compose.yml` | A default secret is public the moment it is committed. The brief also requires a single `docker compose up` on a fresh clone, so requiring a `.env` is out: the `secrets` service fills what `backend/.env` leaves unset. `test/config.test.ts` stops a fallback in code | Add a "dev only" fallback key or password; make `.env` mandatory; give a secret in `.env.example` a value, since a copied placeholder becomes a real, public key |
| Every runtime and package on its newest LTS or stable release | Newest, but only with a support window measured in years: a Node "Current" line or a MySQL innovation release is dropped within months | Pin a Node "Current" line, a MySQL innovation release, or an `-rc`/`-beta` that a `latest` tag points at. Never go back down a MySQL version on a populated volume: the data-directory upgrade is one-way |
| `@fastify/mysql`, with the SQL in one repository per module | The Fastify skill's rule is the official database plugin (`database.md`); a repository keeps every query of a table in one file, where the tenant filter can be checked at a glance | Build SQL from input: every value is a `?` placeholder, and only constants from the repository name a column |
| Migrations are numbered `.sql` files applied by `src/migrate.ts` | No migration tool is needed for plain files run once in order; the runner records each in `schema_migrations` under a named lock | Edit a migration that has run: a database that applied it never sees the change. Add a new file |
| One `.env` per part (`backend/.env`, `frontend/.env`), read by compose through `env_file` | The same file runs the part with or without Docker. Compose interpolates `${...}` only from the root `.env`, so that one keeps `APP_PORT` | Add an `environment:` key to the `secrets` service: it overrides `env_file`, and an empty value there would stop `backend/.env` from setting a secret |
| Backend imports use `@/`, resolved at runtime by a `module.registerHooks` hook (`src/alias.ts`) | Matches the frontend. Node's own `imports` field rejects `@/` and `#/` (only `#name/` works), so a hook is the only way to keep `@/` without a bundler or a new dependency | Start `node` without `--import ./src/alias.ts`: every `@/` import fails with `ERR_MODULE_NOT_FOUND` |
| The backend is run by Node's type stripping, not compiled; `tsc` only checks | The Fastify skill's way (`typescript.md`): no `dist/` to go stale, no build stage, no `tsx`, and `node --watch` restarts on a `.env` edit too | Add enums, namespaces or constructor parameter properties: Node cannot strip them, and `erasableSyntaxOnly` refuses them |
| Backend tests on `node:test` | The Fastify skill's runner (`testing.md`); it runs the same `.ts` files the server runs, with no bundler or alias config of its own | Run test files in parallel: they share one database (`--test-concurrency=1`) |
| The SPA reads through SWR hooks, keyed by endpoint (`hooks/`) | The React skill's `client-swr-dedup`: screens reading the same endpoint share one request and one cached copy; a revisited screen draws at once and refetches behind. A write puts the API's answer in the cache instead of refetching | Load in `useEffect` + `useState` in a page, or write the cache with the `mutate` exported by `swr` (`RULES.md` §6) |
| Every page but Login is a `React.lazy` chunk, preloaded on hover or focus of its link; `qrcode` is imported when MFA setup starts | The React skill's `bundle-dynamic-imports` and `bundle-preload`: the first screen of every visit stays in the main bundle, and the rest arrive before the click. The Suspense boundary sits inside each shell so the tab bar never blanks | Make Login lazy: every visit would wait on a second request for its first screen |
| Pending UI comes from `useTransition`, not a `busy` state | The React skill's `rendering-usetransition-loading`: the flag cannot be left on by a forgotten `finally`, and each card or row owns its own | Share one pending flag across independent actions: one request would disable every button |
| The auth cookie carries a version (`v: 1`); a cookie without one is read as version 1 | The React skill's `client-localstorage-schema`: a later change of shape can refuse an old cookie instead of misreading it | Refuse a cookie without `v`: every signed-in browser would be signed out |
| The SPA does not call `/me` on load | The user is stored with the token at sign-in; a round trip on every load buys only a fresher `mfa_enabled`, which account changes already write back | Add a `/me` call to `AuthProvider`: a dead token already signs out on the first 401 (`routes.test.tsx`) |
| Today is open in the weekly rate, as in the streak | An unchecked habit at 9 a.m. is not a missed day yet | Count today as missed before it ends (`streaks.test.ts` "never counts an open today as missed") |
| Opaque database tokens (`<id>\|<secret>`, hashed), not JWT | A token must die on logout and on a password change, which a stateless JWT cannot do without a denylist, i.e. a table anyway | Switch to JWT without a revocation story |
| Token in an `Authorization` header from a JS-readable cookie, not an httpOnly session cookie | Keeps the API free of CSRF concerns and usable by a non-browser client. The cost is that an XSS could read it, so there must be no XSS (`docs/security.md`) | Add `dangerouslySetInnerHTML` |
| argon2id through `@node-rs/argon2` (64 MiB, 3 passes, 4 lanes) | The Fastify skill's hashing (`authentication.md`): memory-hard, and the package ships prebuilt binaries, so nothing compiles in the image. The PHC string carries its parameters, so they can rise without a migration | Lower the parameters to speed up tests |
| TOTP written by hand (`lib/totp.ts`) | About 60 lines against a published RFC, and the one place a dependency would hold the whole second factor | Replace it without keeping the step-returning `matchCounter` that anti-replay depends on |
| `@fastify/rate-limit` on Redis, one `createRateLimit` checker per bucket | The Fastify skill requires Redis-backed limits in production (`authentication.md`): counts survive a backend restart and span replicas. Login spends three buckets at once and `account-mfa` spans three routes, which per-route `config.rateLimit` cannot express | Count limits in the handler: a malformed request would escape the per-IP buckets. Make `REDIS_URL` required: development outside Docker runs without Redis, on the in-memory store |
| `@fastify/helmet` on the API as well as nginx's headers | The Fastify skill's security baseline (`cors-security.md`): the API answers with the same headers, and a CSP, even when reached without nginx. nginx hides the three headers it sets itself so each leaves once | Add an `add_header` inside nginx's `/api` location to fix a header: it drops every header inherited from `server {}` (`RULES.md` §6) |
| `@fastify/compress`, `@fastify/under-pressure`, a 64 KiB body limit and 30-second timeouts | The Fastify skill's performance and deployment rules: a habit list with a year of logs is tens of KiB, and an overloaded process answers 503 at once instead of queueing | Raise the body limit for a feature without a reason: no valid body comes near it |
| `close-with-grace` for shutdown | Requests in flight get 10 seconds, an uncaught error is logged before the exit, and a second signal exits at once (`deployment.md`) | Call `process.exit` from a handler: it cuts every other request off |
| TypeBox route schemas, checked by Fastify's Ajv before the handler; types through `@fastify/type-provider-typebox` | The Fastify skill's way (`schemas.md`): one declaration types the handler, validates the request and, as a response schema, drops any key it does not list. `ajv-errors` keeps our sentences, and `schemaErrorFormatter` keeps the one 422 shape | Validate by hand inside a handler: it runs after the body was accepted and produces a second error shape. Use the type provider's own validator compiler: it has no `errorMessage`, `$data` or modifying keywords |
| The SPA and API share one origin through nginx | No CORS configuration, no preflights, the backend port stays private | Publish the backend port for the browser to call directly |
| Foreign keys with `ON DELETE CASCADE` | A token or device without a user is meaningless | Rely on cascade to delete user data that should be archived (habit logs) |
| Snake_case on the wire, camelCase in code | One spelling from the database to the client; the repositories alias snake_case columns to camelCase fields | Leak camelCase keys by returning a row (`RULES.md` §1.3) |
| Backend tests against real MySQL, not SQLite | The repositories are MySQL SQL; SQLite would need a second dialect and would hide MySQL-only behaviour | Point `DATABASE_URL` for tests at the app database; `useApp` refuses one without "test" in it |
| Streaks computed from a per-day log, not stored | See `architecture/habits.md` | Store a counter beside the log |
| One phone-width column on every screen | The brand guideline is a mobile app's; a wide desktop layout would be a second design to keep in step | Stretch the column on desktop without redrawing the screens |
